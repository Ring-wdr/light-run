# 음성 안내 보강 시나리오

작성 2026-11-06 · 상태: 구현(Android 실기기 확인 전). 지금 동작은 `docs/PLAN.md` §2-7.

## 0. 문제

지금은 "N분 지났어요"(5분마다)와 목표 안내(절반·5분 전·달성), 내 코스 완료만 말한다.
화면을 안 보고 달리면 다음을 알 수 없다.

- **구간이 언제 바뀌는지**(내 코스). 걷기 2분 → 달리기 1분 같은 인터벌은 화면을 계속 봐야 한다. 지금 가장 큰 공백.
- **코스가 얼마 남았는지.** "15분 지났어요"만으로는 내 코스의 남은 시간을 머리로 계산해야 한다(28분, 27분 30초처럼 딱 떨어지지 않음).

여기서 "코스"는 이 앱의 시간 코스(30분·50분·자유·내 코스)다. 지도 위 길 안내(좌회전 등)는 다루지 않는다(경로 코스가 없음).

## 1. 결정 (2026-11-06)

| 항목 | 결정 |
|---|---|
| 구간 미리 알림 | 제안대로 + 바뀌기 직전 **3·2·1 카운트다운** |
| 구간 시작 | 제안대로(강도 + 시간, 반복 회차, 마지막 구간) |
| 남은 시간 | 제안대로, 단 **내 코스만**(아래 4번) |
| 재개·이어가기 | **지금대로**("다시 시작해요." 등). 구간 상태를 덧붙이지 않는다 |
| 구간 안내 설정 | 설정에 "구간 안내" 켬/끔을 둔다. 기본 켬 |
| 미리 알림 범위 | 모든 전환에 한다. 실기기로 달려 보고 많으면 강도가 올라갈 때만으로 줄인다 |
| 30·50분 코스에 남은 시간 | **현상 유지**(붙이지 않음. 절반·5분 전으로 충분) |
| 플랜 문구 | **현상 유지**(넣지 않음) |

결국 **바뀌는 건 내 코스뿐**이다. 30·50분·자유 코스의 안내는 지금과 같다.

## 2. 원칙 (§2-7에서 바뀌는 것 / 그대로인 것)

- **그대로:** 시간만 말한다. 거리·페이스·GPS 상태는 말하지 않는다. 코칭("페이스를 올리세요")도 하지 않는다.
- **그대로:** 모든 안내는 움직인 시간만으로 정해진다. 구간 경계도 시간으로 정해지므로(`expand`·`segmentAt`)
  새 안내도 **지금처럼 미리 예약**한다 → GPS·화면 상태와 상관없이 제시간에 나온다.
- **바뀜:** "한 번에 한 문장"을 "한 번에 짧은 두 문장까지"로 넓힌다(예: "10분 지났어요. 18분 남았어요.").
- **바뀜:** 내 코스에서 "구간 안내는 하지 않는다"를 뒤집는다. 대신 너무 잦지 않게 아래 규칙으로 줄인다.
- 기록 원본(이벤트)이 아니다. `RunEvent`는 늘리지 않는다.

## 3. 새 안내 목록 (내 코스)

| # | 이름 | 언제 | 문구 예 |
|---|---|---|---|
| A | 시작(보강) | 시작 | "걷기-달리기 입문 코스를 시작할게요. 총 28분, 걷기 5분부터." |
| B | **구간 미리 알림** | 구간이 바뀌기 전(아래 규칙) | "10초 뒤 달리기." / "1분 뒤 걷기." |
| B′ | **카운트다운** | 구간이 바뀌기 3·2·1초 전 | "셋." "둘." "하나." |
| C | **구간 시작** | 구간 경계 | "달리기 1분." / "빠르게 달리기 1분 30초." |
| C′ | 반복 몇 번째 | 반복 블록의 각 회차 첫 구간(C에 붙임) | "달리기 1분. 6번 중 3번째." / "… 6번 중 마지막." |
| C″ | 마지막 구간 | 마지막 구간 시작(C에 붙임) | "걷기 7분. 마지막 구간이에요." |
| D | **남은 시간** | 5분마다 안내에 붙임 | "10분 지났어요. 18분 남았어요." |
| E | 코스 마지막 1분 | 코스 끝 1분 전 | "1분 남았어요." |

- 내 코스 완료 문구("○○ 코스 완료! 계속하거나 종료하세요.")는 그대로. 마지막 구간의 끝이므로 C·B′는 하지 않는다.
- D는 코스를 넘긴 뒤에는 붙이지 않는다("30분 지났어요."만).
- 일시정지·재개·종료·이어가기·토글 문구는 지금과 같다.

### 말하는 형태
- 구간 이름은 `INTENSITY_LABEL`을 쓰되 `fast`는 말할 때 "빠르게 달리기"(화면 라벨 "빠르게"만으로는 어색함).
- 시간: 90초 → "1분 30초", 60초 → "1분", 20초 → "20초". 분 단위는 `spokenMinutes`와 같은 규칙.
- 미리 알림은 조사 없이 "10초 뒤 달리기."로 끝낸다(라벨마다 조사가 달라지는 문제를 피함).
- 카운트다운은 "셋·둘·하나"로 쓴다. 숫자("3")로 넘기면 TTS가 "삼·이·일"로 읽는다.

## 4. 구간 안내 규칙

1. **같은 강도가 이어지면 한 구간으로 본다.** 예: 반복 마지막 걷기 2분 + 정리 걷기 5분 → "걷기 7분." 한 번.
   (화면 차트는 그대로 두고 안내만 합친다)
2. **미리 알림(B):** 지금 구간이 5분 이상이면 1분 전, 30초~5분이면 10초 전, 30초 미만이면 하지 않는다.
   다음이 코스 끝이면 B 대신 E("1분 남았어요.")를 1분 이상 구간에서만 한다.
3. **카운트다운(B′):** 지금 구간이 30초 이상이고 다음 구간이 있을 때만. 각 숫자를 따로 예약한다(T−3, T−2, T−1초).
   30초 미만 구간에서는 하지 않는다(10초 구간이면 3초가 카운트다운에 묻힌다). 코스 끝에는 하지 않는다.
4. **구간 시작(C)은 항상** 한다(10초 구간도). 짧게: 강도 + 시간.
5. C′는 반복이 있는 코스에서 회차 첫 구간에만. 회차 사이 구간(걷기 등)에는 붙이지 않는다.
6. 설정 "구간 안내"가 끔이면 B·B′·C·C′·C″·E를 모두 하지 않는다(A는 지금 문구로, D는 시간 안내 간격을 따른다).

## 5. 겹칠 때 (우선순위)

한 시각에 하나만, 높은 것부터: **코스 완료 > 구간 시작(C) > 카운트다운(B′) > 미리 알림(B·E) > N분 지났어요(D)**.

- **20초 규칙:** 구간 안내(B·B′·C·E) 앞뒤 20초 안에 걸린 "N분 지났어요"는 뺀다.
  말이 큐에 밀려 카운트다운·구간 시작이 늦어지는 걸 막는다(문장 하나가 2~4초).
- 미리 알림 시각이 다른 구간 시작과 같거나 그 뒤 5초 안이면 미리 알림을 뺀다(짧은 구간이 이어질 때).
- 네이티브 모듈의 "밀렸으면 마지막 하나만, 1분 넘게 지난 것은 버림"은 그대로 둔다. 밀렸을 때는 가장 최근 안내가 맞는 정보다
  (카운트다운이 밀렸으면 "하나."나 구간 시작만 나온다).
- 일시정지·재개·종료 멘트는 지금처럼 즉시. 종료만 큐를 비운다.

## 6. 시나리오

### S1. 내 코스 "걷기-달리기 입문" (템플릿, 5분 간격)
구성: 걷기 5분 → (달리기 1분 + 걷기 2분) × 6 → 걷기 5분. 총 28분. 마지막 걷기 2분 + 5분은 합쳐 "걷기 7분".

| 시각 | 안내 | 비고 |
|---|---|---|
| 0:00 | 걷기-달리기 입문 코스를 시작할게요. 총 28분, 걷기 5분부터. | A |
| 4:00 | 1분 뒤 달리기. | B(5분 구간 → 1분 전) |
| 4:57·58·59 | 셋. 둘. 하나. | B′ |
| 5:00 | 달리기 1분. 6번 중 1번째. | C+C′. "5분 지났어요"는 뺌 |
| 5:50 | 10초 뒤 걷기. | B |
| 5:57~59 | 셋. 둘. 하나. | |
| 6:00 | 걷기 2분. | C |
| 7:50 | 10초 뒤 달리기. | |
| 7:57~59 | 셋. 둘. 하나. | |
| 8:00 | 달리기 1분. 6번 중 2번째. | |
| 10:00 | 10분 지났어요. 18분 남았어요. | D(앞뒤 20초 안에 구간 안내 없음) |
| … | (회차마다 같은 패턴) | 15:00·20:00의 "N분 지났어요"는 구간 시작과 겹쳐 뺌 |
| 20:00 | 달리기 1분. 6번 중 마지막. | |
| 20:50 | 10초 뒤 걷기. | |
| 20:57~59 | 셋. 둘. 하나. | |
| 21:00 | 걷기 7분. 마지막 구간이에요. | C+C″(합친 구간) |
| 25:00 | 25분 지났어요. 3분 남았어요. | D |
| 27:00 | 1분 남았어요. | E |
| 28:00 | 걷기-달리기 입문 코스 완료! 계속하거나 종료하세요. | 기존. 카운트다운 없음 |
| 30:00 | 30분 지났어요. | 코스를 넘긴 뒤엔 남은 시간 없음 |

문장 안내 약 30번 + 카운트다운 12번(전환 12번 × 셋·둘·하나). 실기기로 달려 보고 많으면 B를 강도가 **올라갈 때만**(걷기→달리기)으로 줄인다(약 23번).

### S2. 내 코스 "인터벌" (템플릿)
구성: 가볍게 달리기 10분 → (빠르게 1분 + 걷기 1분 30초) × 5 → 가볍게 달리기 5분. 총 27분 30초.

| 시각 | 안내 |
|---|---|
| 0:00 | 인터벌 코스를 시작할게요. 총 27분 30초, 가볍게 달리기 10분부터. |
| 5:00 | 5분 지났어요. 22분 30초 남았어요. |
| 9:00 | 1분 뒤 빠르게 달리기. |
| 9:57~59 | 셋. 둘. 하나. |
| 10:00 | 빠르게 달리기 1분. 5번 중 1번째. ("10분 지났어요" 뺌) |
| 10:50 | 10초 뒤 걷기. |
| 10:57~59 | 셋. 둘. 하나. |
| 11:00 | 걷기 1분 30초. |
| 12:20 | 10초 뒤 빠르게 달리기. |
| 12:27~29 | 셋. 둘. 하나. |
| 12:30 | 빠르게 달리기 1분. 5번 중 2번째. |
| … | |
| 22:30 | 가볍게 달리기 5분. 마지막 구간이에요. |
| 25:00 | 25분 지났어요. 2분 30초 남았어요. |
| 26:30 | 1분 남았어요. |
| 27:30 | 인터벌 코스 완료! 계속하거나 종료하세요. |

- 15:00 "15분 지났어요"는 15:00 구간 시작(3번째 빠르게)과 겹쳐 뺀다. 20:00도 같다.

### S3. 내 코스 "워밍업·달리기·정리" — 긴 구간
구성: 걷기 5분 → 가볍게 달리기 5분 → 달리기 20분 → 걷기 5분. 총 35분.

| 시각 | 안내 |
|---|---|
| 0:00 | 워밍업·달리기·정리 코스를 시작할게요. 총 35분, 걷기 5분부터. |
| 4:00 | 1분 뒤 가볍게 달리기. |
| 4:57~59 | 셋. 둘. 하나. |
| 5:00 | 가볍게 달리기 5분. ("5분 지났어요" 뺌) |
| 9:00 | 1분 뒤 달리기. |
| 9:57~59 | 셋. 둘. 하나. |
| 10:00 | 달리기 20분. |
| 15:00 | 15분 지났어요. 20분 남았어요. |
| 20:00 | 20분 지났어요. 15분 남았어요. |
| 25:00 | 25분 지났어요. 10분 남았어요. |
| 29:00 | 1분 뒤 걷기. |
| 29:57~59 | 셋. 둘. 하나. |
| 30:00 | 걷기 5분. 마지막 구간이에요. |
| 34:00 | 1분 남았어요. |
| 35:00 | 워밍업·달리기·정리 코스 완료! 계속하거나 종료하세요. |

- D의 "남은 시간"은 **코스 전체** 기준이다. 긴 구간 안에서 "구간 N분 남았어요"까지 말하면 둘이 헷갈린다.
  구간 끝은 B(1분 전)와 카운트다운으로 알 수 있다.

### S4. 30분·50분·자유 코스
바뀌지 않는다. 30분 예: 시작 → 5분 → 10분 → 절반(15) → 20분 → 5분 전(25) → 달성(30) → 35분 지났어요.

### S5. 일시정지 · 재개 (내 코스)
S1에서 8:20(달리기 1분 중 20초 지남)에 일시정지.

| 시각(움직인 시간) | 안내 |
|---|---|
| 8:20 | 일시정지했어요. (예약 모두 취소) |
| (재개) 8:20 | 다시 시작해요. (지금 문구 그대로) |
| 8:50 | 10초 뒤 걷기. (다시 예약된 것) |
| 8:57~59 | 셋. 둘. 하나. |
| 9:00 | 걷기 2분. |

- 재개 시점이 미리 알림·카운트다운 시각을 이미 지났으면 지난 것은 말하지 않고 남은 것만 예약한다(지금 규칙 그대로: 지금 이동 시간 이후만).
- 카운트다운 중간(예: T−2초)에 재개하면 "하나."부터 나온다.
- 일시정지 중에는 아무것도 말하지 않는다(지금과 같음).

### S6. 앱이 죽었다가 이어가기 (§2-8)
지금과 같다. 이미 지난 안내는 말하지 않고, 이어간 시점 이후의 구간 안내만 다시 예약한다.

### S7. 기록 중 음성 토글
지금과 같다. 끄면 즉시 조용, 켜면 밀린 안내 없이 이후 예약부터.

### S8. 짧은 구간이 이어지는 코스 (경계 사례)
구성: (빠르게 20초 + 걷기 10초) × 10.
- 모든 구간 < 30초 → 미리 알림·카운트다운 없음. 구간 시작만: "빠르게 달리기 20초. 10번 중 1번째." → "걷기 10초." …
- 10초 구간에서 말이 끝나기 전에 다음 안내가 올 수 있다. 큐에 잇는다(끊지 않음). 실기기에서 밀림이 크면 C′를 줄인다.

### S9. 구간 안내 끔
설정에서 "구간 안내"를 끄면 지금 동작 + D(남은 시간)만 남는다.
S1 예: 시작 → 5분 지났어요. 23분 남았어요. → 10분 … → 25분 지났어요. 3분 남았어요. → 코스 완료.
(구간 안내가 없으므로 20초 규칙으로 빠지는 "N분 지났어요"도 없다)

## 7. 설정

| 항목 | 선택지 | 기본 | 비고 |
|---|---|---|---|
| 음성 안내 | 켬 / 끔 | 켬 | 그대로 |
| 시간 안내 간격 | 끔 / 5분 / 10분 | 5분 | 그대로. D는 이 안내에 붙으므로 끔이면 D도 없음 |
| **구간 안내**(신규) | 켬 / 끔 | 켬 | 내 코스의 B·B′·C·C′·C″·E. 끄면 지금과 같다 |

- 미리 알림 시점(10초/1분)과 카운트다운은 설정으로 빼지 않는다.
- 저장은 `prefs` 키 `voice.segments`(마이그레이션 없음). 기록 중 화면의 스피커 토글은 지금처럼 전체를 끈다.

- **네이티브 tick:** 지금은 1초마다 고정으로 깨어 도래한 예약을 확인한다(`TICK_MS`). 깨는 위상이 예약 시각과 어긋나 최대 1초 늦을 수 있어
  셋·둘·하나가 고르지 않거나 두 개가 한 tick에 몰려 "마지막 하나만" 규칙에 하나가 빠진다.
  → 다음 예약 시각에 맞춰 `postDelayed(next − now)`로 깨도록 바꾼다(최대 1초 제한은 유지).
  iOS·Expo Go의 JS 타이머 경로는 예약마다 `setTimeout`이라 그대로.
- 예약 개수: 코스 최대 3시간, 구간 최소 10초 → 구간 최대 1,080개. 30초 이상 구간만 B·B′(4개)가 붙으므로 최대 약 360 × 5 + 시간 안내 144개.
  네이티브 `schedule`에 한 번에 넘기는 양으로 문제없을 것(실기기에서 확인).
- 테스트(`tests/voice.test.ts`): S1~S3·S8·S9의 예약 목록을 표 그대로 검사, 일시정지 재개 시 fromMs 이후만 나오는지(카운트다운 중간 재개 포함),
  20초 규칙·합치기·30초 미만 미리 알림·카운트다운 없음, 코스 끝에 카운트다운 없음, 30·50분·자유 코스 예약이 지금과 같은지.

- E2E로는 소리를 확인할 수 없다. **실기기 확인 필요:** 화면 끔 상태로 S2(인터벌) 한 번 끝까지 —
